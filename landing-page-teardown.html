Landing Page Teardown Checklist

Use this quick checklist before redesigning, buying ads, or asking for a full landing-page roast. It focuses on clarity, trust, and conversion friction.

Print / save as PDFUse the brief template

1. Hero clarity

A visitor should understand the page before they scroll.

✓

The headline says who it is for and what outcome they get.

✓

The subheadline explains the mechanism or offer in plain language.

✓

The primary CTA describes the next action, not a vague “learn more”.

✓

There is no jargon that only the founder understands.

2. Offer and scope

The page should reduce uncertainty before it asks for commitment.

✓

The visitor can tell what is included and what is not included.

✓

The page explains what happens after someone clicks the CTA.

✓

The copy names a specific buyer, not “everyone”.

✓

If pricing is hidden, the page gives enough context to qualify fit.

3. Trust

Trust does not require fake logos or exaggerated claims.

✓

The page shows real examples, screenshots, process notes, or outcomes.

✓

Testimonials, if used, are specific and not generic praise.

✓

The page avoids guaranteed revenue, traffic, or ranking claims.

✓

The FAQ answers real objections: time, price, fit, process, risk.

4. CTA friction

If the main CTA is too heavy, add a lighter next step.

✓

The main CTA appears near the top and again near the bottom.

✓

The CTA asks for the smallest useful commitment.

✓

There is a secondary CTA for cautious visitors: checklist, brief, sample, or guide.

✓

Forms only ask for information needed to continue the conversation.

5. Agent/API handoff

Agent-built products need operational clarity, not just persuasion.

✓

The page states the exact input another agent or user should provide.

✓

The expected output is concrete: format, fields, file type, or response shape.

✓

The page names common failure modes, limits, and safe fallback behavior.

✓

There is a low-friction test path: sample payload, demo request, sandbox, or brief template.

6. Five-second test

Show the hero section to someone for five seconds, then hide it.

Ask them:

  • Who is this for?
  • What problem does it solve?
  • What is the next action?
  • Why should I trust it?
  • What do I need to send, and what will I get back?

If they cannot answer, fix the hero and handoff details before changing colors, layout, or animations.
